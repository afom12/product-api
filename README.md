# Product CRUD API

A product-management REST API built with **Node.js + Express** and **libSQL (SQLite)**.

- Locally, data is saved in the file `products.db`.
- On Vercel, data is saved in a free **Turso** database (also libSQL/SQLite), so records survive restarts and redeploys.
- Product IDs are generated on the server (UUID).
- 5 fictional products are seeded automatically when the database is empty.

**Live demo:** https://product-api.vercel.app (open it to use the test page)

## Product fields

| Field | Type | Rules |
|---|---|---|
| `id` | string (UUID) | Generated by the server. Cannot be set or changed by the client |
| `name` | string | Required, not empty |
| `category` | string | Required, not empty |
| `price` | number (ETB) | Required, finite number greater than 0 |
| `quantity` | integer | Required, non-negative integer (0, 1, 2, ...) |
| `description` | string | Optional |

## Endpoints

| Method | URL | What it does | Success |
|---|---|---|---|
| GET | `/api/products` | List all products | 200 |
| GET | `/api/products/:id` | Get one product | 200 |
| POST | `/api/products` | Create a product, returns the saved record | 201 |
| PUT | `/api/products/:id` | Update any fields, returns the updated record | 200 |
| DELETE | `/api/products/:id` | Delete a product | 200 |

### Error responses

| Situation | Status | Example body |
|---|---|---|
| Invalid field values | 400 | `{ "error": "Validation failed", "details": ["price must be a finite number greater than 0 (ETB)"] }` |
| Broken JSON body | 400 | `{ "error": "Invalid JSON in request body" }` |
| Empty update body | 400 | `{ "error": "Validation failed", "details": ["Send at least one field to update: ..."] }` |
| ID does not exist | 404 | `{ "error": "Product with id '...' not found" }` |
| Unknown route | 404 | `{ "error": "Route GET /abc not found" }` |

## Run locally

```bash
npm install
npm start          # http://localhost:3000
npm run seed       # optional: reset the database to the 5 seed products
```

Open http://localhost:3000 to use the test page.

## Example requests

```bash
# Create
curl -X POST http://localhost:3000/api/products \
  -H "Content-Type: application/json" \
  -d '{"name":"Gondar Clay Jebena","category":"Home","price":650,"quantity":15,"description":"Traditional clay coffee pot"}'

# Update price and quantity
curl -X PUT http://localhost:3000/api/products/<id> \
  -H "Content-Type: application/json" \
  -d '{"price":700,"quantity":20}'

# Invalid (rejected with 400)
curl -X POST http://localhost:3000/api/products \
  -H "Content-Type: application/json" \
  -d '{"name":"","price":-5,"quantity":2.5}'
```

## Demonstration steps (test page)

1. Click **GET /api/products** to show the 5 seed products.
2. Click **POST /api/products** to create a product. Its ID is filled in automatically. Then click **GET by ID**.
3. Click **PUT price + quantity**, then **GET by ID** to show the saved changes.
4. Click each button under **Invalid examples** to show that they are rejected.
5. Restart the app (locally: stop and run `npm start` again; on Vercel: redeploy), then click **GET by ID**. The product is still there.
6. Click **DELETE by ID**, then **GET by ID**. It returns **404 not found**.

## Deploy to Vercel

1. Create a free database at https://turso.tech and copy its **URL** (`libsql://...`) and an **auth token**.
2. Push this project to GitHub, then import it in Vercel.
3. In Vercel, go to **Settings → Environment Variables** and add:
   - `TURSO_DATABASE_URL` = your Turso URL
   - `TURSO_AUTH_TOKEN` = your token
4. Deploy. The table and 5 seed products are created automatically on the first request.
